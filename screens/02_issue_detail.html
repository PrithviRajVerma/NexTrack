NT-42 Urgent Security
Optimistic Lock: @Version 3

Refresh token rotation with family theft detection & instant session kill

Implement production-grade Refresh Token Rotation (RTR) conforming to OAuth 2.0 Security Best Current Practice (BCP) and NexTrack Architecture Section 7.4. All refresh tokens must belong to a cryptographically secure token family.

// Invariant: Attempted reuse of already-rotated token invalidates entire family
if (currentToken.isRevoked()) {
refreshTokenRepository.revokeFamily(currentToken.getTokenFamily());
throw new SecurityException("Attempted reuse of revoked refresh token");
}

Acceptance Criteria

  • Raw tokens must never be persisted in plaintext; SHA-256 digest stored in token_hash.
  • Refresh token delivered in an HttpOnly; SameSite=Strict; Path=/api/v1/auth cookie.
  • Replay of revoked token executes family invalidation even if exception is thrown (noRollbackFor = SecurityException.class).
  • Returns RFC 7807 Problem Details response with code SECURITY_BREACH_DETECTED.
